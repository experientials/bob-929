# Architecture & Power Path

How the rails come together on a battery-powered USB-C device, and how to get
run-while-charging right. Read this when deciding the overall power topology, before picking
individual chips.

## The three power nodes you must not confuse

- **VBUS** — the USB-C bus voltage coming in from a source (5–20 V) or going out when you source.
- **SYS** — the system rail your device actually runs from. On a good design this is a *distinct
  node* driven by the charger, not just "the battery."
- **BAT** — the raw cell(s).

The relationship between these three nodes *is* the architecture. Get it right and
run-while-charging, instant-on, and clean fuel-gauging all fall out for free. Get it wrong and
you fight all three forever.

## Two charger topologies

### Standalone / "battery-in-the-path" (NO system node)

Cheap linear chargers (TP4056, MCP73831) and the simplest switchers have only VBUS→BAT. The
system is wired directly across **BAT**:

```
VBUS ──[charger]──┬── BAT (cell)
                  └── SYS = BAT  ← load hangs on the battery terminal
```

Consequences — why this is prototyping-only for a run-while-charging product:
- Load current and charge current **sum at the cell terminal**. The charger's current
  regulation and termination detection get confused by the load; termination may never trigger,
  or the cell sees more than the charger thinks.
- **No instant-on from a dead pack** — with a flat battery there's nothing to run the system
  until the cell charges up.
- Fuel-gauging is unreliable because you can't cleanly separate charge from discharge current.
- It *does* technically "run while charging," which is why people ship it anyway — but it's the
  wrong tool for anything that must be robust.

### Power-path / NVDC (narrow VDC) — the right answer here

A power-path charger has a real **SYS** node between VBUS and BAT, with an internal FET (often
called BATFET) between SYS and BAT:

```
VBUS ──[charger]──┬────────── SYS ── system load
                  │            │
                  └─[BATFET]───┘
                               │
                              BAT (cell)
```

Behavior:
- **Input present:** the charger regulates SYS from VBUS and powers the system *directly*; it
  charges BAT from whatever input budget is left after the system takes its share (this is
  "dynamic power management" / input-current limit sharing). The system runs at full speed even
  with a dead battery — **instant-on**.
- **Load spike beyond input budget:** the charger opens the BATFET into *supplement mode* and
  the battery **tops up the system** so SYS doesn't collapse. This is how a 5 V/1.5 A charger
  can power a device whose peak draw exceeds 7.5 W.
- **Input removed:** BATFET connects BAT→SYS seamlessly; the system never sees a glitch.

"NVDC" = the SYS rail is held just above the battery voltage (a narrow window), so the system
sees a fairly stable rail regardless of charge state. This is the standard topology for phones,
tablets, and anything that must run and charge at once. **This is the topology to use.**

Charger parts that implement it: BQ24250 (1S, the bob-929 part), BQ25896/98 (1S, +boost OTG,
+D±/PD detect), BQ25792/98 (1–4S buck-boost), MP2731, and the host-side BQ25703A. Full charger
selection is in `chargers-and-cells.md`.

## Where each rail comes from (device-side block diagram)

A typical single-cell device with one sink port and one source port, no PD controller:

```
                 ┌─ ESD/OVP ─┐
 charger/PC ─VBUS┤ (TPD6S300)├─VBUS_IN ─[power-path charger]─┬─ SYS ─┬─ buck ─ 3V3 (logic)
   (sink port)   └───────────┘   Rd on CC                    │       └─ buck ─ 1V8 / core
                                                             BAT (1S LiPo, 3.0–4.35 V)
                                                             │
                    5V boost ── VBUS_OUT ─[ESD]─ USB-C (source port), Rp on CC, USB2 mux
```

Notes:
- **SYS is the trunk.** Everything the device runs on comes from SYS via bucks/LDOs, whether the
  energy is currently arriving from USB or from the cell.
- The **source port's 5 V** is generated by a boost from the 1S battery (a 1S cell is 3.0–4.35 V,
  below 5 V, so you *boost*). From a 2S pack you'd *buck* down to 5 V instead — see below.
- A tiny always-on supervisor rail (e.g. VCC_RTC / an MSP430 domain) can hang off SYS or the
  battery through a low-Iq LDO so the device can wake and manage state in deep sleep.

## Cell arrangement changes the topology

Covered fully in `chargers-and-cells.md`; the architectural summary:

- **1S** (one cell, 3.0–4.35 V): SYS ≈ battery voltage. Bucks down to 3V3/1V8. To source 5 V you
  **boost**. Currents are high at low voltage (I = P/V), so trunk traces are fat. Simplest
  charger market.
- **2P** (two cells in parallel): electrically identical to 1S, just double capacity. **No
  balancing, no topology change** — this is the low-risk way to "use two cells."
- **2S** (two cells in series, 6.0–8.7 V): halves trunk current for the same power (nice for
  routing), but needs a **2S charger with cell balancing**, a 2S protection/BMS, and a **buck**
  to reach 3V3 (an LDO from 8 V wastes most of the energy as heat). To source 5 V you **buck**
  (easier than the 1S boost). Choose 2S when peak power is high enough that 1S trunk currents
  get ugly, and you're willing to take on balancing.

If the requirement is genuinely "one **or** two cells" across product variants, a **1–4S
buck-boost charger (BQ25792/98)** lets one board populate as 1S or 2S — the buck-boost handles
both battery-below-VBUS and battery-above-VBUS cases without a topology change. That flexibility
is the main reason to pay for a buck-boost.

## Sanity checks for any architecture

- Trace/copper for the SYS trunk sized for **peak** current (battery-supplement case), not
  average.
- Input-current-limit set to what the *weakest* expected source can give (a 5 V/0.5 A port
  shouldn't cause a brownout — that's what DPM/supplement mode is for).
- A path for **dead-battery boot**: the system must come up from input alone.
- Reverse-current protection on any node that can be back-driven (source port, or VBUS when the
  battery voltage exceeds a collapsed VBUS).
